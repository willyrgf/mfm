# State Layer Relocation Plan

> Status: Completed.
> Date: 2026-02-19.
> Scope: Move reusable state crates out of `crates/ops/` so repository structure matches the `Operation` (planning) vs `State` (execution) contract.
> Migration policy: hard cutover for internal paths; no compatibility shims/re-exports.
> Execution model: commit-by-commit on a shared dev branch (no PR slicing required).
> Completion note: the reusable state crates now live under `crates/states/common`, `crates/states/keystore`, and `crates/states/aave-v3`. This document is retained as the historical implementation plan for that migration.

## 1. Objective

Make the physical repo layout reflect the logical architecture:

- `crates/ops/*-op`: operation planners only.
- shared state layer: reusable executable states in dedicated non-ops paths.

This removes the current ambiguity where reusable state crates live under `crates/ops/`.

## 2. Scope

In scope:
- Relocate shared state crates currently under `crates/ops/*-common`.
- Update workspace membership, path dependencies, architecture verification, and architecture docs.
- Keep behavior unchanged (layout refactor only).

Out of scope (optional follow-up):
- Renaming Rust package names/crate IDs (`mfm-op-*` -> `mfm-state-*`).
- Refactoring op-local states into shared states.

## 3. Current Baseline

Shared state crates currently in misleading locations:
- `crates/ops/common` (`mfm-op-common`)
- `crates/ops/keystore-common` (`mfm-op-keystore-common`)
- `crates/ops/aave-v3-common` (`mfm-op-aave-v3-common`)

Other state-oriented crate (already outside `ops`):
- `crates/evm-runtime` (`mfm-evm-runtime`)

Path-coupled tooling that must be updated:
- workspace members in `Cargo.toml`
- `crates/tools/architecture-verify/src/main.rs` default shared roots and keystore tx state probe path
- discovery docs generated by check (`docs/repo-index.json`, `docs/repo-map.md`)
- architecture docs and audit docs with hardcoded crate paths

## 5. Migration Strategy

Use small, atomic commits.
Do path relocation first while preserving package names to reduce code churn.
Breaking intermediate commits are acceptable on this dev branch; stabilization commits should restore green checks.

### Commit 0: Bridge Support (tooling preflight)

Goal:
- Allow temporary mixed layouts during migration.

Changes:
- Update `mfm-architecture-verify` to accept both old and new shared-state roots.
- Update keystore tx-sign local-only check to probe both paths:
  - old: `crates/ops/keystore-common/src/states/tx.rs`
  - new: `crates/states/keystore/src/states/tx.rs`

Rationale:
- Prevent avoidable churn while moving crates one-by-one.

Checkpoint validation:
- `nix run .#check`
- `nix run .#test`

    - `crates/ops/*-op/Cargo.toml` that depend on `mfm-op-common`
    - `crates/evm-runtime/Cargo.toml`

## 6. Commit Breakdown (Recommended)

2. `state-layout: move mfm-op-common to crates/states/common`
3. `state-layout: move mfm-op-keystore-common to crates/states/keystore`
4. `state-layout: move mfm-op-aave-v3-common to crates/states/aave-v3`
5. `state-layout: cut over docs/tooling/discovery to new state paths`
6. `state-layout: rename state packages (optional)`

Recommended practice:
- allow quick WIP commits between these checkpoints if needed
- squash/reword later only if desired (not required for this branch)

## 7. Risks and Mitigations

Risk: broken path dependencies across many `Cargo.toml` files.
- Mitigation: move one crate per checkpoint commit; run `nix run .#check` immediately after each move.

Risk: architecture verifier fails during intermediate states.
- Mitigation: Commit 0 bridge support and explicit fallback roots/paths.

Risk: drift in discovery/docs artifacts.
- Mitigation: run discovery refresh in the cutover commit and include generated updates in the same commit.

Risk: stale audit docs with old path evidence.
- Mitigation: either update evidence paths or mark historical snapshots as point-in-time records.

## 8. Acceptance Criteria

Migration is complete when all are true:
- No shared reusable state crate remains under `crates/ops/`.
- `crates/ops/` contains only op planner crates (`*-op`) and op-specific implementation code.
- Architecture verifier default shared roots point to the new state-layer paths.
- Workspace builds/tests pass via canonical commands:
  - `nix run .#check`
  - `nix run .#test`
  - `nix run .#ci -- --full --summary`
- Docs and discovery artifacts reflect new paths.

## 9. Outcome
