## Existing requirements trace

Portfolio admission checks source order, bounded nonempty collections, exact ledger envelope,
source identity uniqueness, source-aligned public execution descriptors and one route per
collection. Snapshot retains confirmed quantities and descriptors. Enrichment retains caller-
required sources or nonzero raw quantities while filtering descriptors alongside sources.
Native identity and protocol qualification stay outside Portfolio. Existing quote labels have
no price/FX contract and cannot establish fiat value. The existing independent native fixture
supplies fixed point `fixed-test-point` on `other-ledger`, raw amount 42 for account `retained`,
0 otherwise, and source denomination 0. These are scripted holdings, not live chain support.

The implemented path is native Prepare -> shared Observe -> native Confirm -> shared
Consolidate, retaining each source. A proposed complete-collection Read can repeat unfinished
sources; no reviewed product requirement establishes whether source-level durable progress is
required. Source-stage tests alone cannot establish that requirement.

## Common semantic contract

Eligible sharing is unsigned fungible quantity in native base units with explicit denomination,
ledger, target and observation point. Asset/account identity uses owner-native data in existing
BalanceTarget/LedgerIdentity/ObservationPoint envelopes. Mapping changes representation only;
it may not transform debt, spendable-only authority, locked/rebasing shares or fiat valuation into
this quantity. Each owner owns its supported trust, coherence and authenticated rejection.
Original native receipt Object and factory-selected code reference survive exactly. Unsupported
meaning rejects at checked admission or uses a distinct contract; no generic protocol branch.

## Predetermined extension observations

1. First owner instances `route-a` and `route-b` use one installed factory. Binding differences
   remain declaration data; changing a route acquires no new generic association entry.
2. Second owner uses distinct typed binding, receipt, fault and resource owner. Its successful
   collection contains source `retained` raw `42`, denomination 0, exact other-ledger identity,
   fixed-test-point point; source `empty` raw `0`. No USD/EUR or scalar lifecycle meaning is
   asserted. Independently scripted arguments and stored native originals establish expected
   facts, not matching hot/cold projections alone.
3. A whole-account batch receipt (ledger name + fixed snapshot + account-keyed entries) differs
   structurally from a scalar request-relative EVM receipt. The owner must select the exact
   requested account and reject absent/duplicate or wrong-unit entries without inventing 0.
4. Local request/binding route, ledger, target or supported-unit disagreement fails before native
   resource IO; no authenticated operational outcome is fabricated. An authenticated external
   wrong identity/ref or unsupported native outcome retains a distinct owner rejection/fault
   with the actual causal fields.
5. A source whose meaning is `liability` is rejected as unsupported holdings, not negated,
   flattened or returned as successful raw quantity.
6. Equal family IDs and equal remaining stored contracts with a behavior-changing Observation-
   only specialization expose the lost schema discriminator. Fresh private-owner collision must
   reject before attachment. Distinct committed semantic revision or checked binding meaning
   disambiguates. Existing-wire descriptor evidence does not establish target cold replacement
   identity; sole restart replacement under unchanged IDs remains revision trust.

## Counterexamples

Central protocol branch, copied support matrix, native meaning coerced into holdings, second
factory for compatible binding-only reuse, lost originals/cause/point, or pre-IO request mismatch
becoming authenticated failure disproves the named sharing/locality subclaim. Inadequate target
identity seam leaves specialization claim Unvalidated rather than supported by unrelated IDs.
